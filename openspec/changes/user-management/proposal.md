# Proposal: 用户管理（账号体系 + 每用户阅读进度）

## 为什么做

当前应用只有一个环境变量配置的共享访问密码，所有访问者共用同一个身份与同一份阅读进度。实际使用中这是硬伤：

- **书可以共享，进度不能共享**。同一台机器上两个人读同一本《宠魅》，会互相把对方的读到位置改成自己的。
- **没有身份**，无法区分「谁读到哪」，也无法为不同的人分别留痕。

因此引入最小可用的账号体系：**书库全体共享，阅读进度按人独立**。这是对早期「不做多用户」这一非目标的有意反转。

## 变更范围

- **账号**：用户名 + 密码登录，取代共享访问密码；密码用标准 KDF 加盐哈希存储
- **首次运行引导**：首次启动时创建第一个管理员；此后不再开放自助注册
- **仅管理员建号**：不提供开放注册，避免暴露到公网后被滥用
- **共享书库**：所有登录用户看到同一批书；记录导入者（信息性）
- **每用户进度**：阅读进度与「当前书」按用户隔离；两人同读一本书互不干扰
- **管理员用户管理**：列出/创建/删除用户、重置密码、授予或取消管理员
- **品牌标识**：换成自研的极简几何标记 + 项目自有名称（详见设计文档的商标说明）

## 非目标（Non-goals）

- 不做开放注册、邮箱验证、找回密码（管理员重置即可）
- 不做第三方登录（OAuth）与两步验证
- 不做按书库隔离（每本书对所有用户可见，这是本次明确选择）
- 不做用户配额、审计日志、细粒度 ACL
- **不使用 OpenAI / ChatGPT 的名称、logo 或商标**（沿用既有约束）
- 不改动流式阅读（SSE）与章节解析的行为

## 成功标准

1. 全新部署首次打开时出现「创建管理员」引导，且该引导需要服务器启动日志中打印的一次性口令才能完成。
2. 登录页为**用户名 + 密码**；错误凭据返回 401 并给出明确提示。
3. 管理员可在界面中创建用户、重置密码、删除用户、授予管理员。
4. 非管理员访问用户管理接口返回 403。
5. 两个用户读同一本书时，各自进度互不影响（有测试覆盖）。
6. 老数据升级：既有《宠魅》与其进度自动归属到首个管理员，不丢数据。
7. 左上角显示自研标识与「墨鱼」文字，不出现任何 OpenAI/ChatGPT 元素。
8. 全部测试通过（pytest / vitest / Playwright）。
