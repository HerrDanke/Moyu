# Proposal: 界面改造为 ChatGPT 风格

## 为什么做

当前界面是「顶部横条 + 横向书目下拉 + 全宽消息流 + 底部输入框」的常规布局，视觉上更像内部工具而非聊天产品。用户要求整个网站的 UI 对齐 https://chatgpt.com/ 的观感，以获得更自然、更「像在跟大模型对话」的阅读体验——这正是本产品「伪装 AI」的核心卖点。

## 变更范围（结构级重构）

- **去掉顶部横条**：书单/导入入口移入左侧栏（对应 ChatGPT 的对话历史列表）
- **侧栏书架**：每本书显示自身进度；**切换书籍等价于开新会话**（清空消息区并显示该书的空状态）
- **居中内容列**：消息区限宽居中，不再全宽铺满
- **底部悬浮圆角输入框**：发送按钮内嵌；空状态时输入框居中，发出首条消息后落到底部
- **助手正文去气泡**：助手消息为纯文本流（ChatGPT 特征），用户消息为浅灰圆角气泡
- **生成中指示**：三点脉冲显示在消息流内（助手即将输出处），输入框按钮同时变为「停止」
- **阅读列可切换**：宽松（680px + 中文首行缩进，默认）／紧凑（768px 无缩进）
- **主题**：默认浅色，保留深色切换（持久化于 localStorage）

## 非目标（Non-goals）

- **不改后端**：所有 API、SSE 协议、数据结构保持不变。本次是纯前端改造。
- 不做多会话历史（ChatGPT 的对话列表语义由「书架」承载，不新增会话模型；切书只是清空当前上下文）。
- 不做移动端原生 App；仅保证窄屏侧栏可折叠为抽屉。
- 不引入 UI 组件库（继续用原生 CSS + 少量 hooks），避免体积与依赖膨胀。
- 不改变「快速阅读」「断句续读」「进度百分比」等既有功能的语义。
- 不加入头像、渐变、AI 装饰图形；不使用 OpenAI/ChatGPT 的品牌元素。

## 成功标准

1. 桌面端首屏视觉结构为：左侧栏（我的书架）+ 居中内容列 + 底部悬浮输入框。
2. 空状态（已选书但无消息）显示当前书与进度 + 可点击的示例指令，而非空洞问候语。
3. 助手消息无背景气泡；用户消息为浅灰圆角气泡并右对齐。
4. 默认浅色；切换深色后刷新仍保持，且首屏无主题闪烁。
5. 阅读宽度可在宽松/紧凑间切换并持久化。
6. 窄屏（<768px）侧栏为可开关抽屉，具有键盘可达性（Esc 关闭、焦点管理）。
7. 键盘焦点可见；系统开启减少动效时动画被关闭。
8. **既有功能零回归**：登录、导入、下一章、进度、快速阅读、搜索、切书全部照常。
9. 全部测试通过，E2E 迁移到稳定的 `data-testid` 选择器。
