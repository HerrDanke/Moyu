# Proposal: 阅读快捷工具条与章节目录

## 为什么做

现在唯一的交互方式是**手打指令**（「下一章」「第 20 章」），没有任何可点的控件。对「读小说」这种高频翻页场景，每次都要打字是明显的体验短板；而且**界面上从来没有章节列表**——想跳到某一章只能猜数字。

## 变更范围

- **阅读工具条**：输入框上方一行常驻按钮 —— 下一章 / 上一章 / 目录 / 跳转章节
- **章节目录抽屉**：点「目录」弹出当前书的章节列表，可搜索、当前章高亮，点章节即跳转
- **跳转章节**：点「跳转」把输入框预填为「第 」并聚焦，补数字回车即可（**复用已有指令解析，不新增后端逻辑**）
- **精简空状态**：去掉与工具条重复的示例按钮，改为一句引导

## 非目标（Non-goals）

- 不改后端 API（目录直接用现成的 `GET /api/books/{id}/chapters`）
- 不做滚动位置的书签、不做多章连续阅读、不做章节内搜索
- 不做目录的拖拽排序或分组
- 不引入虚拟列表库（自己写一个轻量窗口化实现）

## 成功标准

1. 输入框上方常驻一行按钮，窄屏下可横向滚动不破版。
2. 生成中（流式）时发送类按钮禁用，避免并发指令。
3. 「目录」抽屉能打开当前书的完整章节列表，**1807 章下滚动与搜索依然流畅**（只渲染可视窗口）。
4. 抽屉打开时自动定位到当前章并高亮；点任一章节即跳到该章。
5. 「跳转」按钮把输入框预填为「第 」并聚焦，光标在末尾。
6. 空状态不再出现与工具条重复的按钮。
7. 既有功能零回归；新增用例覆盖，全量测试通过。
