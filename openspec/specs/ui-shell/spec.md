## Requirements

### Requirement: 应用外壳布局
**ID:** ui-shell.layout

界面采用 ChatGPT 式外壳：左侧栏承载书架与设置，主区为居中内容列，底部为悬浮输入框。后端 API 契约不受影响。

#### Scenario: 左侧栏书架
- Given 已导入若干书籍
- When 打开应用
- Then 左侧栏在「我的书架」分区下列出全部书籍，当前书高亮显示
- Then 每本书显示其自身的阅读进度
- Then 侧栏提供「＋ 导入新书」入口
- When 点击某本书
- Then 该书被设为当前书并同步到服务端

#### Scenario: 居中内容列
- Given 正在阅读某章
- Then 消息区限制在居中的阅读列内，不在宽屏上全宽铺满
- Then 助手消息为无背景的纯文本流，用户消息为浅灰圆角气泡并右对齐

#### Scenario: 空状态
- Given 已选定一本书但消息区为空（首次打开或刚切过书）
- Then 内容区居中显示：当前书名与进度、以及可点击的示例指令（如「下一章」「上一章」「跳到第 12 章」）
- Then 不出现「你好，我是你的阅读助手」这类无信息量的问候语

#### Scenario: 底部悬浮输入框
- Given 消息区为空
- Then 输入框在内容区垂直居中显示
- When 发送第一条消息
- Then 输入框移动到底部并固定，移动过程不发生宽度变化、不做位置动画

#### Scenario: 窄屏抽屉式侧栏
- Given 视口宽度小于 768px
- Then 侧栏默认隐藏，左上角显示开关按钮
- When 点击开关
- Then 侧栏以抽屉形式滑出并可关闭；选择书籍后自动收起

### Requirement: 切书即开新会话
**ID:** ui-shell.session

侧栏切换书籍等价于 ChatGPT 的切换对话：进入该书的独立阅读上下文。

#### Scenario: 切换书籍清空消息区
- Given 我正在读《凡人修仙传》且消息区有内容
- When 我在侧栏点击《宠魅》
- Then 消息区被清空，显示《宠魅》的空状态与其阅读进度
- Then 服务端当前书同步为《宠魅》

#### Scenario: 通过指令切书行为一致
- Given 我正在读《凡人修仙传》
- When 我输入「读《宠魅》」
- Then 消息区清空并进入《宠魅》的阅读上下文（与点击侧栏一致）

### Requirement: 阅读列与排版
**ID:** ui-shell.reading

正文排版针对中文长时间阅读优化，并提供可切换的阅读宽度。

#### Scenario: 阅读宽度开关
- Given 侧栏底部提供「阅读宽度」开关
- When 选择「宽松」（默认）
- Then 阅读列为 680px，正文首行缩进 2em、段间距大于行距
- When 选择「紧凑」
- Then 阅读列为 768px，正文无首行缩进、段落更紧凑
- Then 该偏好持久化，刷新后仍生效

#### Scenario: 章节标题具有层次
- Given 助手输出一章内容
- Then 章节标题渲染为独立块（字号更大、加粗、上下留白），与正文明显区分

#### Scenario: 流式滚动不晃眼
- Given 正在流式输出长章节
- Then 自动滚动使用非平滑方式，且仅当用户已位于底部时跟随
- When 用户向上滚动
- Then 停止自动跟随并显示「回到底部」入口

### Requirement: 主题
**ID:** ui-shell.theme

默认浅色主题，支持切换到深色并持久化。

#### Scenario: 默认浅色
- Given 首次访问且本地无主题记录
- Then 以浅色主题渲染

#### Scenario: 深色切换持久化
- When 切换到深色主题
- Then 立即生效并写入本地存储，刷新后仍为深色

#### Scenario: 首屏无主题闪烁
- Given 本地已保存深色主题
- When 打开页面
- Then 首屏即按深色渲染，不出现先浅后深的闪烁

#### Scenario: 阅读正文与光标可读
- Given 深色主题
- Then 正文字色为柔和的浅灰而非纯白，正文与背景对比度不低于 7:1
- Then 打字机光标使用与正文同系的颜色，宽度为细竖条而非实心方块
- Then 用户气泡与背景在深色下仍可肉眼区分

### Requirement: 无障碍
**ID:** ui-shell.a11y

界面需可键盘操作，并尊重系统的减少动效偏好。

#### Scenario: 键盘焦点可见
- When 使用 Tab 键在侧栏项、输入框、按钮间移动
- Then 每个可聚焦元素都有明显可见的焦点描边

#### Scenario: 尊重减少动效偏好
- Given 系统开启了「减少动态效果」
- Then 打字机光标闪烁、三点脉冲、平滑滚动与输入框位移过渡均被关闭

#### Scenario: 生成状态可被读屏感知
- Given 正在流式生成章节
- Then 通过无障碍实时区域播报「正在生成第 N 章」，而不只靠视觉动画

#### Scenario: 抽屉侧栏的键盘可达性
- Given 窄屏下侧栏以抽屉形式打开
- Then 抽屉具有对话框语义，焦点被限制在抽屉内，按 Esc 可关闭
- Then 关闭后焦点回到侧栏开关按钮

### Requirement: 身份与账号界面
**ID:** ui-shell.identity

界面需要表达「当前是谁在用」，并提供账号相关入口。

#### Scenario: 登录页为用户名 + 密码
- Given 库中已存在用户且未登录
- Then 登录页包含用户名与密码两个输入框，以及明确的错误提示位

#### Scenario: 首次运行引导页
- Given 库中没有任何用户
- Then 展示「创建管理员」引导页，包含用户名、密码、引导口令三项
- Then 提示引导口令可在服务端启动日志中找到

#### Scenario: 侧栏用户区
- Given 已登录
- Then 侧栏底部显示当前用户名与其身份（管理员 / 普通用户）
- Then 提供「退出登录」入口

#### Scenario: 管理员专属入口
- Given 当前用户是管理员
- Then 侧栏显示「用户管理」入口
- Given 当前用户是普通用户
- Then 不显示该入口

#### Scenario: 用户管理对话框的可操作性
- Given 以管理员身份打开用户管理
- Then 可在弹窗内查看用户列表、创建用户、重置密码、切换管理员、删除用户
- Then 弹窗支持 Esc 关闭并把焦点收回到触发按钮
- Then 危险操作（删除用户）需要二次确认

### Requirement: 品牌标识
**ID:** ui-shell.branding

左上角展示项目自身的标识与名称，视觉语言保持克制。

#### Scenario: 显示自研标识
- Given 打开应用
- Then 左上角显示一个原创的极简几何标记，配项目自有名称「墨鱼」
- Then 标记为单色、无渐变，并随主题自动适配颜色

#### Scenario: 不出现第三方品牌元素
- Given 任意界面状态
- Then 不出现 OpenAI / ChatGPT 的名称、logo 或仿冒图形
- Then 不暗示本应用与 OpenAI 存在任何关联

#### Scenario: 窄屏下的标识表现
- Given 视口宽度小于 768px 且侧栏收起
- Then 标识不遮挡内容列，侧栏展开按钮仍然可点

### Requirement: 阅读快捷工具条
**ID:** ui-shell.reading-toolbar

在输入框上方提供一行常驻快捷按钮，把最高频的几个动作变成可点控件；跳转类操作复用既有指令，不新增后端能力。

#### Scenario: 下一章 / 上一章
- Given 我已选定一本书
- When 点击「下一章」
- Then 以「下一章」这条指令发起对话，行为与手动输入完全一致（含流式输出与进度推进）
- When 点击「上一章」
- Then 以「上一章」发起对话

#### Scenario: 生成中禁用发送类按钮
- Given 正在进行流式生成
- Then 「下一章」「上一章」不可点击，与输入框的禁用状态一致
- Then 「目录」「跳转章节」仍可用（它们不发起请求）

#### Scenario: 跳转章节预填输入框
- When 点击「跳转章节」
- Then 输入框被预填为「第 」并获得焦点，光标位于末尾
- Then 不发起任何请求
- When 用户补全数字并回车
- Then 跳到对应章节（复用既有的跳转指令）

#### Scenario: 窄屏下不破版
- Given 视口宽度小于 768px
- Then 工具条横向可滚动，按钮不换行、不挤压阅读列

### Requirement: 章节目录
**ID:** ui-shell.table-of-contents

提供当前书章节列表的浏览与跳转入口；在超长书目（如 1807 章）下仍需保持流畅。

#### Scenario: 打开目录定位到当前章
- Given 我正在读《宠魅》第 2 章
- When 点击「目录」
- Then 打开章节抽屉，列表自动滚动到第 2 章并高亮它
- Then 抽屉带有对话框语义，按 Esc 可关闭，关闭后焦点回到「目录」按钮

#### Scenario: 超长书目只渲染可视窗口
- Given 当前书有 1807 章
- Then 抽屉不为全部章节创建 DOM 节点，只渲染可视区域附近的行
- Then 滚动与搜索保持流畅

#### Scenario: 搜索章节
- Given 目录已打开
- When 在搜索框输入关键词
- Then 列表按章节标题做子串过滤
- Then 过滤后点击某一章，跳转的是该章的**真实章号**，而不是过滤结果中的位次

#### Scenario: 点击章节跳转
- Given 目录已打开
- When 点击某一章
- Then 以「第 N 章」发起阅读并关闭抽屉
- Then 该章成为当前阅读位置（进度随之更新）
- When 点击的是不存在的章号（超出范围）
- Then 由既有指令逻辑给出范围提示，不出现异常

#### Scenario: 无书或空目录
- Given 尚未选定任何书，或该书没有任何章节
- When 点击「目录」
- Then 抽屉展示明确的空状态提示，而不是报错或空白

### Requirement: 空状态精简
**ID:** ui-shell.empty-state-simplified

空状态不再重复工具条已经提供的操作。

#### Scenario: 空状态不含重复按钮
- Given 已选定书但消息区为空
- Then 显示书名与阅读进度
- Then 显示一句引导文案，提示可用下方按钮或直接打字
- Then 不再出现「下一章」「上一章」「跳到第 12 章」这类与工具条重复的按钮

### Requirement: 设置面板
**ID:** ui-shell.settings-panel

侧栏底部提供统一的设置入口；原先散落在侧栏的开关收纳进面板，侧栏恢复简洁。

#### Scenario: 打开与关闭设置
- Given 已登录
- Then 侧栏底部显示「设置」按钮
- When 点击它
- Then 打开设置面板（对话框语义）
- Then 按 Esc 或点击遮罩可关闭，关闭后焦点回到「设置」按钮

#### Scenario: 侧栏精简
- Given 打开应用
- Then 侧栏底部不再直接出现 主题 / 阅读宽度 / 快速阅读 / 退出登录 这些开关
- Then 侧栏保留：书架、导入新书、当前书进度、设置入口、用户区
- Then 管理员仍能从侧栏进入「用户管理」

#### Scenario: 面板内可完成原有操作
- Given 设置面板已打开
- Then 面板内包含 深色主题、宽松排版、快速阅读 三个开关，行为与之前完全一致
- Then 面板内包含「退出登录」，点击后回到登录页

#### Scenario: 窄屏下可用
- Given 视口宽度小于 768px
- Then 设置入口位于抽屉式侧栏内，打开面板后内容不溢出、可滚动

### Requirement: 思考强度控制
**ID:** ui-shell.thinking-intensity

以「AI 思考强度」的叙事提供文字生成速度控制，贴合产品「伪装成大模型」的定位。

#### Scenario: 五档滑杆
- Given 设置面板已打开
- Then 显示一个五档的「思考强度」滑杆，并标注当前档位名称
- Then 档位为：极速 / 迅捷 / 标准 / 深入 / 沉思
- Then 说明文案表明它影响正文逐字出现的节奏

#### Scenario: 调速同时作用于服务端与打字机
- Given 我把思考强度调高
- Then 不仅服务端分批之间的停顿变短，前端逐字渲染的速率也同步加快
- （否则长章节会被打字机自身的速率下限拖住，调速上限形同虚设）

#### Scenario: 调整即时生效
- Given 我把思考强度从「标准」调到「沉思」
- When 我发起下一次阅读
- Then 正文逐字出现的节奏明显变慢
- When 我调到「迅捷」
- Then 节奏明显变快

#### Scenario: 按用户保存
- Given 我把思考强度设为「深入」
- When 刷新页面或换一个浏览器登录同一账号
- Then 设置面板中的档位仍为「深入」，且阅读节奏随之生效

#### Scenario: 未设置时回落到服务端默认
- Given 我从未调整过思考强度
- Then 使用服务端环境变量 `TYPING_SPEED` 作为默认节奏

#### Scenario: 非法值被拒绝
- Given 有人直接调用设置接口
- When 提交超出允许范围的速度值（如 0、负数或极大值）
- Then 返回 400 且不写入
